# Milestone 2 — השלמת ניהול ההוצאות בדף הבית: תוכנית בנייה

> מקורות: `MILESTONES.md` (Milestone 2), `PRD.md` (4.2, 4.3, Edge Cases), `ARCHITECTURE.md` (2.4 REST API, 2.5 Data Flow, ADR-1/2), `DESIGN.md` (1.1 דף הבית), `wireframes-desktop.png`, `wireframes-mobile.png`, `mockups-desktop.png`, `mockups-mobile.png`, `style-guide.png`.
> נקודת פתיחה (הקוד הקיים מ-Milestone 1): `GET`/`POST /api/expenses`, טופס הוספה, רשימה (טבלה במחשב, כרטיסים בטלפון), מצבי טעינה/ריק/שגיאה, ולידציה משותפת ב-`shared/expenseSchema.ts`, Plugin ל-API מקומי ב-`vite.config.ts`.

## 1. מטרה ותחום

**בסוף ה-Milestone:** בדף הבית אפשר לעדכן הוצאה דרך Modal, למחוק הוצאה אחרי אישור, ולמיין את הרשימה לפי תאריך, קטגוריה וסכום — הכול מול Supabase **Development**, במחשב ובטלפון.

**בתחום:** `PUT`/`DELETE /api/expenses/:id`; Modal עדכון; Dialog אישור מחיקה; מיון; הודעות הצלחה/שגיאה; טיפול בהוצאה שכבר לא קיימת.

**מחוץ לתחום:** דף הפילטרים (M3), דו"חות (M4), ייצוא ואודות (M5), כל נגיעה ב-Production (M6). **אין צורך ב-Migration** — הטבלה, ה-Trigger של `updated_at` וההרשאות של `app_backend` (כולל `update`, `delete`) כבר קיימים.

## 2. API

קובץ חדש: `api/expenses/[id].ts` (נתיב דינמי של Vercel). ה-`id` נלקח מכתובת הבקשה (החלק האחרון בנתיב).

| בקשה | התנהגות |
|------|----------|
| `PUT /api/expenses/:id` | `id` שאינו UUID → `400 INVALID_ID`. גוף לא תקין → `400 VALIDATION_ERROR` עם `fields` (אותה ולידציה כמו ב-POST, כולל תאריך עתידי לפי `Asia/Jerusalem`). `update ... where id = $id returning ...`: אין שורה → `404 NOT_FOUND`; יש → `200` עם ההוצאה המעודכנת. |
| `DELETE /api/expenses/:id` | `id` שאינו UUID → `400 INVALID_ID`. `delete ... where id = $id returning id`: אין שורה → `404 NOT_FOUND`; יש → `204` בלי גוף. |
| Method אחר על `/:id` | `405 METHOD_NOT_ALLOWED` |

- `updated_at` מתעדכן על ידי ה-Trigger הקיים. בבנייה בודקים בפועל שה-Trigger עובד כשהמשתמש הוא `app_backend` (ב-M1 בוטלה ממנו הרשאת `execute` על הפונקציה; ב-PostgreSQL ההרשאה נבדקת רק ביצירת ה-Trigger, אבל מוודאים). אם נכשל — Migration קטנה שמחזירה `grant execute ... to app_backend`, מורצת על Development בלבד.
- קוד משותף: בדיקת UUID ב-`api/_lib/http.ts` (`isUuid`), והודעות שגיאה אחידות (בלי פרטי SQL).
- **Plugin ה-API המקומי** (`vite.config.ts`): כשאין קובץ תואם לנתיב (`/api/expenses/<id>`), מחפשים בתיקיית האב קובץ בשם `[...].ts` (כמו ב-Vercel). שינוי קטן, נשאר תואם ל-ADR-2.

## 3. דף הבית — ממשק

### 3.1 כפתורי "עדכון" ו"מחיקה"
- **מחשב:** עמודה חדשה "פעולות" בטבלה (כמו ב-Wireframe), עם שני כפתורי אייקון: עיפרון (Cyan) ופח (Hot Pink), כמו ב-Mockup. לכל כפתור תווית נגישה ו-tooltip: "עדכון" / "מחיקה" (כולל פרטי ההוצאה לקורא מסך, למשל "עדכון הוצאה: סופרמרקט, 249.90").
- **טלפון:** אותם שני אייקונים בצד השמאלי של כל כרטיס (כמו ב-Wireframe וב-Mockup הנייד). שטח לחיצה של 44px לפחות.
- הערה על סתירה קלה בין התמונות: ה-Wireframe של המחשב מציג את הפקדים כטקסט, וה-Mockup ושני ה-Wireframes של הטלפון כאייקונים. בחרתי אייקונים עם תווית "עדכון"/"מחיקה" (נגישה + tooltip) — זה ממלא את התוכן מה-Wireframe ואת המראה מה-Mockup.

### 3.2 Modal "עדכון הוצאה"
- רכיב `Modal` כללי על בסיס האלמנט `<dialog>` של הדפדפן (`showModal()`): רקע מעומעם, סגירה ב-Esc או בלחיצה על "ביטול"/X, הפוקוס חוזר לכפתור שפתח אותו.
- תוכן: כותרת **"עדכון הוצאה"** ואותו טופס כמו "הוספת הוצאה" (`ExpenseForm` מקבל `mode="edit"` וערכים התחלתיים), מאוכלס בפרטי ההוצאה. כפתורים: **"שמירה"** (Primary) ו-**"ביטול"** (Secondary) — כמו ב-Style Guide.
- **שמירה:** ולידציה בדפדפן → `PUT` → רק אחרי `200` ה-Modal נסגר, הרשימה נטענת מחדש מהשרת, ומופיעה הודעה "ההוצאה עודכנה".
- **שגיאת ולידציה** (בדפדפן או `400` מהשרת): ה-Modal נשאר פתוח עם הערכים שהוקלדו וההודעות מתחת לשדות — אפשר לתקן.
- **כשל רשת/שרת:** ה-Modal נשאר פתוח, הודעה אדומה "העדכון נכשל, ההוצאה לא עודכנה. נסו שוב."
- **`404`:** ה-Modal נסגר, הרשימה נטענת מחדש, הודעה "ההוצאה לא נמצאה — ייתכן שכבר נמחקה."

### 3.3 Dialog "מחיקת הוצאה"
- אותו רכיב `Modal`, קטן יותר. כותרת **"מחיקת הוצאה"**, טקסט: "למחוק את ההוצאה?" ומתחתיו פרטי ההוצאה (תאריך, תיאור/קטגוריה, סכום), ושורה "לא ניתן לבטל פעולה זו."
- כפתורים: **"מחיקה"** (Primary בגרדיאנט Pink→Magenta) ו-**"ביטול"** (Secondary). הפוקוס ההתחלתי על "ביטול", כדי שלחיצת Enter לא תמחק בטעות.
- **ביטול / Esc:** נסגר בלי שום בקשה לשרת.
- **אישור:** `DELETE` → אחרי `204` הדיאלוג נסגר, הרשימה נטענת מחדש, הודעה "ההוצאה נמחקה". בזמן הבקשה הכפתור מושבת ("מוחק…").
- **כשל:** הדיאלוג נשאר פתוח עם הודעה "המחיקה נכשלה, ההוצאה לא נמחקה. נסו שוב." · **`404`:** כמו בעדכון.

### 3.4 מיון
- **מחשב:** כותרות העמודות **תאריך**, **קטגוריה**, **סכום (₪)** הן כפתורים. לחיצה ממיינת לפיהן; לחיצה נוספת הופכת כיוון. חץ ▲/▼ ליד העמודה הפעילה, ו-`aria-sort` לנגישות. עמודת "תיאור" ו"פעולות" לא ממוינות (PRD 4.2 מגדיר שלוש עמודות).
- **טלפון:** אין כותרות בכרטיסים, ולכן מעל הרשימה תיבת בחירה קטנה **"מיון"** עם האפשרויות: "תאריך (מהחדש לישן)", "תאריך (מהישן לחדש)", "קטגוריה (א–ת)", "קטגוריה (ת–א)", "סכום (מהגבוה לנמוך)", "סכום (מהנמוך לגבוה)". שני התצוגות משתמשות באותו מצב מיון.
- **ברירת מחדל:** תאריך, מהחדש לישן. ברירת המחדל בלחיצה ראשונה: תאריך וסכום — יורד; קטגוריה — עולה (א–ת).
- **שובר שוויון:** תאריך יורד ואז סדר היצירה (כמו בשרת), כדי שהסדר יהיה יציב.
- המיון נעשה בדפדפן על הרשימה שנטענה (ARCHITECTURE 2.5), בפונקציה טהורה `sortExpenses(expenses, { key, direction })`: סכום משווה באגורות שלמות; קטגוריה עם `localeCompare('he')`.
- מצב המיון נשמר בזמן עדכון/מחיקה/הוספה (לא חוזר לברירת המחדל אחרי פעולה).

### 3.5 הודעות
- רכיב `Toast` קטן (במקום ה"ההוצאה נשמרה" הנוכחי): "ההוצאה נשמרה" / "ההוצאה עודכנה" / "ההוצאה נמחקה", נעלם אחרי 3 שניות, `role="status"`. בטלפון — מעל פס הניווט התחתון.
- מצבי טעינה/ריק/כשל טעינה הקיימים נשארים כמו שהם (כבר נבדלים זה מזה). כשיש רענון אחרי פעולה, הרשימה הקיימת נשארת מוצגת עד שהחדשה מגיעה (בלי הבהוב של "טוען הוצאות…").

**הנוסחים בסעיפים 3.2–3.5 הם הצעה** (ה-PRD לא קובע אותם) — אפשר לשנות.

## 5. בדיקות אוטומטיות

- **API (`PUT`/`DELETE`):** `200` לעדכון תקין (כולל המרת אגורות), `400` לכל כלל ולידציה ול-UUID שגוי, `404` כשאין שורה, `204` במחיקה, `405`, `503`/`500` בלי חשיפת פרטים.
- **מיון:** כל שלושת המפתחות בשני הכיוונים, ברירת מחדל, שובר שוויון, סכומים כמו `"9.90"` מול `"100.00"` (מספרי ולא טקסטואלי), קטגוריות בעברית.
- **ממשק:** לחיצה על כותרת משנה סדר ו-`aria-sort`; Modal עדכון — לא שולח קלט שגוי, נשאר פתוח בכשל, נסגר רק בהצלחה; Dialog מחיקה — "ביטול" לא קורא ל-API, "מחיקה" קורא פעם אחת; `404` מציג הודעה ולא הצלחה.
- `npm test` ו-`npm run build` עוברים.

## 6. סדר העבודה בבנייה

1. API: `[id].ts`, עזרי `http.ts`, בדיקות; תמיכה ב-`[param]` ב-Plugin.
2. בדיקה אמיתית מול Development (בדפדפן/`fetch`): PUT/DELETE תקינים, `404`, UUID שגוי; וידוא ש-`updated_at` מתעדכן כ-`app_backend`.
3. `sortExpenses` + בדיקות.
4. `Modal`, `Toast`, הרחבת `ExpenseForm` למצב עריכה.
5. `EditExpenseModal`, `DeleteExpenseDialog`, `ExpenseList` (פעולות + מיון), `SortSelect`, חיבור ב-`HomePage`.
6. בדיקות ממשק.
7. בדיקה בדפדפן, מחשב (1280px) וטלפון (375px): עדכון תקין + Reload, עדכון שגוי, ביטול מחיקה, מחיקה, מיון בשלוש העמודות ובבחירת הטלפון, הוצאה שנמחקה בחלון אחר (`404`), כשל רשת (עדכון/מחיקה), רשימה ריקה.
8. `npm test`, `npm run build`, סימון 🟡 ב-MILESTONES.md, סגירת השרת.
