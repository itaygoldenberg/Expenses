# Milestone C — עיצוב מחדש של המסכים הקיימים: תוכנית בנייה

> מקורות: `MILESTONES.md` (Milestone C), `PRD.md` 3.0 (3.ב, 4.1, 4.4, 4.5, 4.7, 4.8, 4.9, Edge Cases), `DESIGN.md` 3.0 (1.0, 1.2, 1.3, 1.4, 1.8, 1.9, סעיף 2), `ARCHITECTURE.md` 3.0 (2.3, 2.4, 2.9, 2.12).
> נקודת פתיחה (הקוד הקיים): Design System מ-B ב-`src/ui/` + `AppShell`; המסכים הישנים (`HomePage`, `FiltersPage`, `ReportsPage`, `AboutPage`) עדיין בעיצוב הישן דרך שמות המשתנים הישנים ב-`tokens.css`. כל דף טוען את הנתונים בעצמו (`useExpenses`). ה-API: `GET/POST /api/expenses`, `PUT/DELETE /api/expenses/:id`. בטבלה `expenses` אין עדיין `kind`.

## 1. מטרה ותחום

**בסוף ה-Milestone:**
- **דף ראשי** חדש (`/`) עם KPI, מגמה, פילוח, אחרונות ופעולה מהירה — מנתונים אמיתיים בלבד.
- **דף "הוצאות"** (`/expenses`) — כל הרישומים, חיפוש + סינון משולב ב-AND, מיון, טבלה במחשב / כרטיסים בטלפון, עדכון ומחיקה. `/filters` מפנה ל-`/expenses`.
- **"הוספה" מכל דף** — הטופס נפתח כ-Sheet בטלפון / Modal במחשב.
- **סוג רישום:** הוצאה / זיכוי / הכנסה (`kind`), כולל Migration ב-Development, ולידציה, תצוגה וחישובי "נטו".
- **דו"חות** עם בחירת תקופה והשוואה לתקופה קודמת; ייצוא CSV/PDF עם עמודת "סוג", בעיצוב החדש.
- **אודות** כדף Portfolio.
- כל המסכים על רכיבי `src/ui`; שמות המשתנים הישנים נמחקים מ-`tokens.css`.

**מחוץ לתחום:** התחברות ושם משתמש (D) — הברכה כללית; בידוד (E); ייבוא, שדה "מקור" ושדות הייבוא (F) — ראו סעיף 9; ניתוחים מתקדמים (G). אין שינוי ב-Production.

## 2. נתונים ו-API — סוג רישום (`kind`)

**Migration** `supabase/migrations/<timestamp>_add_expense_kind.sql` (תואמת-לאחור, עם תסריט ביטול בהערה):
- `alter table public.expenses add column kind text not null default 'expense' check (kind in ('expense','refund','income'))` — כל הרשומות הקיימות הופכות ל"הוצאה", שום רשומה לא משתנה אחרת ולא נמחקת.
- `category` הופכת ל-nullable, עם CHECK: `kind = 'income'` ⇔ `category is null`. האילוץ הקיים "אחר דורש תיאור" נשאר.
- **הרצה ב-Development בלבד** (דרך Supabase MCP אם מחובר, אחרת ב-SQL Editor בדפדפן יחד איתך), ובדיקה שהרשומות הקיימות קיבלו `expense`. Production — רק ב-H.

**ולידציה משותפת** (`shared/expenseSchema.ts`, אותה בדפדפן ובשרת):
- `kind` אופציונלי בגוף הבקשה, ברירת מחדל `expense` (תאימות-לאחור); ערך אחר → שגיאה.
- הוצאה / זיכוי: קטגוריה חובה. הכנסה: קטגוריה נמחקת (נשמר `null`).
- שאר הכללים כמו היום (סכום חיובי עד ₪100,000, תאריך לא עתידי, "אחר" דורש תיאור, תיאור עד 200).

**API:** `GET` מחזיר גם `kind`; `POST`/`PUT` מקבלים ושומרים `kind`. הטיפוס `Expense` מקבל `kind` ו-`category: Category | null`.

**הגדרות מדדים** (`src/features/metrics/` — פונקציות טהורות עם בדיקות דיוק, PRD 4.8):
- **הוצאות (נטו)** = Σ הוצאות − Σ זיכויים, לתקופה / קטגוריה.
- **הכנסות** = Σ הכנסות.
- **כמות** = מספר רישומי הוצאה (בלי זיכויים והכנסות).
- **Pie / פילוח:** רק קטגוריות שהנטו שלהן חיובי.
- **שינוי באחוזים** מוצג רק כששתי התקופות כוללות רישומי הוצאה/זיכוי; בסיס 0 או שלילי → לא מוצג.
- הכול בחישוב שלמים (אגורות), בלי שגיאות עיגול.

## 3. מבנה, ניווט ונתונים משותפים

- **נתיבים:** `/` דף ראשי · `/expenses` הוצאות · `/reports` דו"חות · `/about` אודות · `/filters` → הפניה ל-`/expenses` · `/design-system` (פיתוח בלבד).
- **ניווט** (`navigation.ts`): ראשי · הוצאות · ➕ · דו"חות · עוד (אודות). ב-Sidebar: ראשי, הוצאות, דו"חות; אודות בתחתית.
- **`ExpensesProvider`** ברמת ה-`AppShell`: טוען את הרישומים פעם אחת, ומספק `state`, `reload` ופעולות `create/update/remove`. כל הדפים וה-Sheet של ההוספה משתמשים בו, כך שרישום שנוסף מכל דף מופיע מיד בכל מקום (ADR-11 קצר).
- **"הוספה" (➕ / כפתור ב-Sidebar / פעולה מהירה):** פותח `AddExpenseSheet` (`Sheet` מ-B — מלמטה בטלפון, Modal במחשב) מכל דף. אחרי שמירה: Toast "נשמר", הטופס נסגר, הרשימות מתעדכנות. ההתנהגות הזמנית מ-B (מעבר לבית ופוקוס) מוסרת.

## 4. טופס רישום (הוספה ועדכון)

`ExpenseForm` נבנה מחדש על רכיבי `src/ui`:
- `SegmentedControl` "הוצאה / זיכוי / הכנסה" בראש הטופס (ברירת מחדל הוצאה).
- **סכום** גדול (`TextField numeric` עם ₪), תאריך (ברירת מחדל היום, `max` היום), קטגוריה (`SelectField`, **מוסתרת בהכנסה**), תיאור.
- הודעות שגיאה ליד השדה (כמו היום), `Button loading` בשמירה, שגיאת שרת בפס בתוך הטופס.
- עדכון: אותו טופס בתוך `Modal` (כמו היום); מחיקה: `ConfirmDialog` עם פרטי הרישום, "מחיקה" (Coral) ו"ביטול" עם פוקוס ראשוני. ההתנהגות ב-404 ("ההוצאה לא נמצאה…") נשמרת.

## 5. המסכים

### 5.1 דף ראשי (`/`) — DESIGN 1.2, PRD 4.7
- **ברכה כללית** ("שלום!" + החודש הנוכחי) — שם המשתמש ייכנס ב-D. **פעולה מהירה:** "הוספת הוצאה" (פותח את ה-Sheet). "ייבוא דוח" יתווסף ב-F.
- **KPI** (4 כרטיסים במחשב, 2×2 בטאבלט, שורה נגללת של כרטיסים בטלפון בתוך מסגרת — העמוד לא נגלל הצידה):
  1. הוצאות החודש (נטו) + שינוי באחוזים מול החודש הקודם (רק כשיש נתונים לשניהם; עלייה ב-Coral, ירידה ב-Emerald).
  2. הכנסות החודש.
  3. רישומים החודש (כל הסוגים).
  4. הקטגוריה הגדולה החודש (לפי נטו) — "—" כשאין.
  - מספרים ב-Inter `tabular-nums`, ספירה עדינה כשהערך משתנה (כבויה ב-reduced-motion).
- **מגמה:** עמודות של 6 החודשים האחרונים (הוצאות נטו), וקו הכנסות רק אם יש הכנסות בטווח.
- **פילוח קטגוריות** החודש: Donut + מקרא עם ערכים.
- **אחרונות:** 6 הרישומים האחרונים, עם Badge של הסוג, וקישור "לכל ההוצאות".
- **מצבים:** Skeletons בטעינה; משתמש בלי רישומים → כרטיס ריק עם "הוספת הוצאה ראשונה"; חודש בלי רישומים → KPI של 0 ו"אין עדיין רישומים החודש" בגרפים; שגיאה → `ErrorState` עם "נסו שוב".

### 5.2 הוצאות (`/expenses`) — DESIGN 1.3, PRD 4.5
- **סרגל עליון:** חיפוש טקסט (בתיאור, בלי הבחנה בין אותיות גדולות/קטנות, מתעלם מרווחים מיותרים) + כפתור "סינון" (עם מונה פילטרים פעילים) + "הוספה".
- **סינון:** שורה נפתחת במחשב / `Sheet` בטלפון — שנה → חודש → יום (ההיררכיה הקיימת), סכום מקסימלי, **סוג**, **קטגוריה**. כל התנאים ב-AND יחד עם החיפוש. **Chips** של פילטרים פעילים עם X, ו"איפוס".
- **מחשב/טאבלט:** `DataTable` — תאריך, תיאור, קטגוריה (Badge עם נקודת צבע הקטגוריה), סוג (Badge), סכום (Emerald לזיכוי/הכנסה, רגיל להוצאה), פעולות (עדכון, מחיקה עם `aria-label` מלא כמו היום). מיון בכותרות: תאריך, קטגוריה, סכום (ברירת מחדל תאריך מהחדש לישן — הלוגיקה הקיימת).
- **טלפון:** כרטיסים (סכום בולט, תיאור · קטגוריה, תאריך, Badge סוג, כפתורי פעולה) + `SelectField` "מיון".
- **שורת סיכום** מעל הרשימה: מספר הרישומים המוצגים.
- **מצבים:** Skeleton; "עדיין אין רישומים" (+ הוספה); "אין רישומים שתואמים לחיפוש" (+ איפוס); שגיאת טעינה + "נסו שוב".
- הדף `FiltersPage` והקבצים שלו נמחקים; הבדיקות שלו עוברות לבדיקות דף ההוצאות (אותה התנהגות סינון + החדשים).

### 5.3 דו"חות (`/reports`) — DESIGN 1.4, PRD 4.8
- **סרגל עליון:** `SegmentedControl` תקופה — **הכול** (ברירת מחדל, ההתנהגות של היום) · החודש · 3 חודשים · שנה · טווח מותאם (שני שדות תאריך); `SegmentedControl` מדד (₪ / כמות); מתג **"השוואה לתקופה הקודמת"** (מושבת ב"הכול").
- **הגדרות התקופות** (ראו סעיף 9): "החודש" = החודש הקלנדרי הנוכחי; "3 חודשים" = החודש הנוכחי ושני הקודמים; "שנה" = 12 החודשים האחרונים כולל הנוכחי; "טווח מותאם" = מתאריך עד תאריך. **התקופה הקודמת** = טווח באותו אורך שמסתיים יום לפני תחילת התקופה.
- **כרטיס סיכום:** הוצאות נטו, הכנסות וכמות לתקופה; כשההשוואה פעילה — הערך של התקופה הקודמת והשינוי באחוזים (רק כשיש נתונים לשתיהן).
- **Donut לפי קטגוריות** (נטו, רק חיובי) לתקופה הנבחרת; כשההשוואה פעילה, המקרא מציג גם את ערך התקופה הקודמת לכל קטגוריה.
- **עמודות לפי שנים / חודשים** — כמו היום (הוצאות נטו / כמות), בעיצוב החדש.
- **Tooltips** בזכוכית כהה, RTL, ערך מלא. לכל גרף סיכום טקסטואלי נסתר לקורא מסך.
- **ייצוא** — כרטיס בתחתית בעיצוב החדש (`SegmentedControl` היקף, `SelectField`, `Button` "הורדת CSV" ראשי / "הורדת PDF" משני). המנגנון הקיים נשמר: פילטרים עצמאיים, הודעת "אין רישומים לייצוא", שם הקובץ.
  - **CSV ו-PDF:** עמודת **"סוג"** חדשה; הכנסה בלי קטגוריה מוצגת כ"—"; סכומים חיוביים כמו היום (הסוג מבחין). שורת סיכום ב-PDF: הוצאות נטו והכנסות. צבעי כותרת ה-PDF מתעדכנים לפלטה החדשה. העברית ב-PDF ממשיכה לעבוד לפי ADR-5.

### 5.4 אודות (`/about`) — DESIGN 1.8, PRD 4.9
- **Hero:** התמונה הקיימת בעיגול עם טבעת אור עדינה, "איתי גולדנברג — Itay Goldenberg", התיאור שסופק; זה לצד זה במחשב, אחד מתחת לשני בטלפון; כניסה מדורגת עדינה.
- **על האפליקציה:** פסקה קצרה.
- **יכולות:** Feature Cards לפי DESIGN (התחברות פרטית, רישום מהיר, ייבוא דוחות, דו"חות וגרפים, ייצוא CSV/PDF, פרטיות). יכולות שעוד לא נבנו (התחברות, ייבוא, פרטיות) מסומנות ב-Badge **"בקרוב"** עד ה-Milestone שלהן — כדי לא להציג משהו שעוד לא קיים (ראו סעיף 9).
- **Technology Stack:** Chips רק של מה שבשימוש בפועל: React, TypeScript, Vite, React Router, PostgreSQL (Supabase), Vercel Functions, Chart.js, pdfmake, Papa Parse, Zod, Vitest.
- **קישורים** GitHub / LinkedIn — לא מוצגים עד שתספק קישורים.
- **Footer:** "Developed by Itay Goldenberg" + שורה עובדתית: "פותח בעזרת כלי AI (Claude Code) כחלק מתהליך הפיתוח".

## 7. בדיקות
- **ולידציה וסוגים** (`shared`): `kind` חסר → הוצאה; ערך לא חוקי → שגיאה; הוצאה/זיכוי בלי קטגוריה → שגיאה; הכנסה עם קטגוריה → נשמרת בלי קטגוריה.
- **API:** POST/PUT עם `kind` נשמרים ומוחזרים נכון; בקשה ישנה בלי `kind` עדיין עובדת.
- **דיוק מדדים:** נטו עם זיכויים (כולל קטגוריה שהזיכוי בה גדול מההוצאה), הכנסה לא נספרת בהוצאות, כמות = רישומי הוצאה בלבד, שינוי באחוזים רק כשיש נתונים לשתי התקופות, גבולות תקופות (סוף חודש, שנה מעוברת, מעבר שנה), טווח מותאם.
- **דף ראשי:** KPI נכונים על נתוני בדיקה; השוואה מוסתרת בלי חודש קודם; מצב ריק.
- **הוצאות:** חיפוש + שנה/חודש/יום + סכום + סוג + קטגוריה ב-AND; Chips מסירים פילטר; איפוס; מיון; `/filters` מפנה; עדכון ומחיקה (כולל 404) — הבדיקות הקיימות מותאמות למבנה החדש, באותה התנהגות.
- **Sheet ההוספה:** נפתח מכל דף, שומר, מתעדכן בכל הדפים, הקטגוריה מוסתרת בהכנסה.
- **דו"חות וייצוא:** תקופות והשוואה; CSV עם "סוג"; PDF מכיל את עמודת הסוג ונשאר תקין בעברית.
- **כל הבדיקות הקיימות** (Regression) + `npm run build`.
- **בדפדפן:** 375 / 820 / 1280 / 1440px — כל המסכים, בלי גלילה אופקית, מקלדת, reduced-motion ו-reduced-transparency; זרימה מלאה: הוספה (3 סוגים) → עדכון → מחיקה → סינון וחיפוש → דו"חות → ייצוא CSV/PDF ופתיחתם (PDF נבדק עם pdf.js כמו ב-M5, בלי לפתוח את הקובץ בחלון שמוריד אותו).
- נתוני בדיקה ב-Dev מסומנים "בדיקה"/"דוגמה"; לא נמחקים רישומים קיימים.

## 8. סדר העבודה בבנייה
1. Migration `kind` → הרצה ובדיקה ב-Development.
2. `shared` (טיפוסים, ולידציה) + API + בדיקות.
3. פונקציות המדדים והתקופות + בדיקות דיוק.
4. `ExpensesProvider`, נתיבים, ניווט, `AddExpenseSheet`, `ExpenseForm` החדש.
5. דף ההוצאות (חיפוש, סינון, Chips, טבלה/כרטיסים, עדכון/מחיקה) + הפניית `/filters`.
6. הדף הראשי.
7. דו"חות + ייצוא (CSV/PDF עם "סוג").
8. אודות.
9. ניקוי השמות הישנים והקבצים שאינם בשימוש.
10. בדיקה בדפדפן בכל הגדלים, `npm test`, `npm run build`, ADR-11, סימון 🟡 ב-MILESTONES.md, סגירת השרת.

## 9. הנחות שכדאי לאשר
1. **"מקור" (ידני/ייבוא):** DESIGN מזכיר סינון ואייקון לפי מקור, אבל השדה `source` שייך ל"שדות הייבוא" של F, ועד אז כל הרישומים ידניים. ההצעה: הסינון והאייקון של "מקור" ייכנסו ב-F.
2. **הגדרות התקופות בדו"חות** כמו בסעיף 5.3, ובנוסף אפשרות **"הכול"** כברירת מחדל — כדי שהדו"חות של היום (כל הנתונים) ימשיכו לעבוד.
3. **אודות:** יכולות שעוד לא נבנו מסומנות "בקרוב".
4. **דף ראשי:** בלי כפתור "ייבוא דוח" עד F; "רישומים החודש" סופר את כל הסוגים.
