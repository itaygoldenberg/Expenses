# PRD – מערכת לניהול הוצאות

## 1. רקע ומטרות

### א. מטרת המוצר
לאפשר למשתמש יחיד לנהל את הוצאותיו האישיות, לסנן אותן, לנתח אותן באמצעות גרפים ולייצא אותן לקבצים.

### ב. תיאור הבעיה
משתמש המעוניין לעקוב אחר הוצאותיו זקוק למקום מרוכז לרישום הוצאות, איתור הוצאות מתאריכים מסוימים, הבנת התפלגות ההוצאות ושמירת דו"חות לשימוש מחוץ לאתר.

### ג. תיאור הפתרון
אתר רספונסיבי בעברית, עם ארבעה דפים: בית, פילטרים, דו"חות ואודות. האתר מאפשר ניהול הוצאות, סינון משולב, הצגת גרפים וייצוא CSV ו-PDF. הנתונים נשמרים במסד נתונים בענן ב-Supabase באמצעות Backend המתארח ב-Vercel ונטענים מחדש בביקורים חוזרים. קוד המקור נשמר ב-GitHub, וגרסאות Production מתעדכנות אוטומטית לאחר דחיפה לענף `main` והצלחת בדיקות ו-Database Migrations.

## 2. קהלי יעד וצרכי משתמשים

### א. User Personas – פרסונות משתמשים
- **משתמש פרטי:** אדם המעוניין לתעד הוצאות, לעיין בהן, להבין כיצד הן מתחלקות לפי קטגוריות ותקופות ולייצא אותן. משתמש באתר ממחשב או מטלפון, ללא חשבון משתמש.
- **תלמיד/ה המפתח/ת את האתר:** מציג/ה בדף האודות הסבר על המערכת, תיאור אישי ותמונה.

### ב. User Stories – סיפורי משתמש
- כמשתמש פרטי, אני רוצה להוסיף הוצאה עם קטגוריה, תיאור, סכום ותאריך, כדי שאוכל לתעד את הוצאותיי.
- כמשתמש פרטי, אני רוצה לעדכן או למחוק הוצאה קיימת, כדי שאוכל לתקן את הרישומים שלי.
- כמשתמש פרטי, אני רוצה למיין את רשימת ההוצאות, כדי שאוכל למצוא מידע בקלות.
- כמשתמש פרטי, אני רוצה לשלב סינון לפי תאריך וסכום מקסימלי, כדי שאוכל לצפות בהוצאות העונות לתנאים שבחרתי.
- כמשתמש פרטי, אני רוצה לצפות בהתפלגות ההוצאות לפי קטגוריות ובשינויים לפי שנים וחודשים, כדי להבין את דפוסי ההוצאות שלי.
- כמשתמש פרטי, אני רוצה לעבור בין סכומי הוצאות למספר הוצאות בגרפים, כדי לנתח את הנתונים בשתי דרכים.
- כמשתמש פרטי, אני רוצה לייצא את כל ההוצאות או הוצאות מסוננות ל-CSV או ל-PDF, כדי שאוכל לשמור את הנתונים מחוץ לאתר.
- כמשתמש פרטי, אני רוצה שהנתונים שלי יישמרו ב-Database וייטענו מחדש בין ביקורים, כדי שלא אצטרך להזינם מחדש.
- כמבקר באתר, אני רוצה לקרוא על המערכת ועל מי שפיתח/ה אותה, כדי להבין את ייעודה.

## 3. זרימות וחוויית משתמש

### א. User Journey – מסע המשתמש
המשתמש נכנס לאתר ונוחת בדף הבית. הוא רושם הוצאות באמצעות הטופס, וצופה בהן בטבלה שמתחתיו. לפי הצורך, הוא מעדכן הוצאה בחלון Modal או מוחק הוצאה לאחר אישור. בהמשך הוא עובר לדף הפילטרים כדי להתמקד בהוצאות מסוימות, או לדף הדו"חות כדי לראות גרפים ולייצא נתונים. בביקור חוזר, ההוצאות נשאבות ממסד הנתונים ב-Supabase באמצעות ה-Backend.

### ב. User Flows – זרימות המשתמש

**הוספת הוצאה**
1. פתיחת דף הבית.
2. בחירת קטגוריה, הזנת סכום, בחירת תאריך (ברירת המחדל: היום), והזנת תיאור לפי הצורך.
3. לחיצה על כפתור ההוספה.
4. בדיקת תקינות הנתונים; אם קיימת שגיאה, הצגתה למשתמש לצורך תיקון.
5. אם הקלט תקין: שליחת בקשת שמירה ל-Backend, שמירת ההוצאה ב-Supabase והצגתה בטבלת ההוצאות רק לאחר אישור ההצלחה.

**עדכון הוצאה**
1. לחיצה על "עדכון" בשורת הוצאה בדף הבית.
2. פתיחת Modal עם נתוני ההוצאה הקיימים.
3. שינוי הפרטים ואישור העדכון.
4. ביצוע אותן בדיקות תקינות כמו בהוספה.
5. שמירת השינויים ועדכון הטבלה אם הקלט תקין.

**מחיקת הוצאה**
1. לחיצה על "מחיקה" בשורת הוצאה בדף הבית.
2. הצגת בקשת אישור למחיקה.
3. באישור: מחיקת ההוצאה מ-Supabase באמצעות ה-Backend, ולאחר הצלחה הסרתה מהטבלה. בביטול: שמירת ההוצאה ללא שינוי.

**סינון הוצאות**
1. מעבר לדף הפילטרים.
2. בחירת שנה; אפשר להוסיף חודש ויום באופן היררכי, וכן סכום מקסימלי.
3. הצגת ההוצאות העונות לכל התנאים שנבחרו, בטבלה עצמאית בדף הפילטרים.
4. אפשרות למיון התוצאות דרך כותרות העמודות.

**צפייה בדו"חות**
1. מעבר לדף הדו"חות.
2. צפייה בגרף Pie לפי קטגוריות ובגרף עמודות לפי שנים או חודשים.
3. בחירת אופן המדידה: סכום בשקלים או מספר הוצאות.
4. בגרף העמודות: מעבר בין תצוגה שנתית לחודשית; בתצוגה החודשית בחירת שנה.

**ייצוא נתונים**
1. בדף הדו"חות, בחירה בין ייצוא כלל ההוצאות לייצוא הוצאות מסוננות.
2. במקרה של ייצוא מסונן, הגדרת פילטרים עצמאיים לפי שנה, חודש, יום וסכום מקסימלי, הניתנים לשילוב.
3. לחיצה על כפתור CSV או PDF.
4. הורדת קובץ בפורמט הנבחר למכשיר המשתמש. הפילטרים לייצוא אינם משנים את הגרפים.

### ג. UX Requirements – דרישות חוויית משתמש
- ממשק מלא בעברית ובכיווניות RTL, לרבות תפריטים, טפסים, הודעות, כפתורים וכותרות.
- Layout אחיד בכל הדפים, עם כותרת ראשית, תפריט ניווט ועיצוב אסתטי.
- תצוגה רספונסיבית ונוחה לשימוש ב-Desktop וב-Mobile.
- הצגת שגיאות ולידציה ברורות לצד האפשרות לתקן את הנתונים.
- הצגת הודעות ידידותיות במקום טבלאות ריקות כשאין הוצאות, ובמקום גרפים חסרי נתונים.
- כשסינון אינו מחזיר תוצאות, הצגת הודעה ברורה שאין התאמות.
- מיון אינטראקטיבי בטבלאות דף הבית ודף הפילטרים, עם ברירת מחדל של תאריך מהחדש לישן.

## 4. דרישות פונקציונליות

### א. Features & Functional Requirements – פיצ'רים ודרישות פונקציונליות

#### 4.1 מבנה האתר וניווט
- האתר יכיל ארבעה דפים: **בית**, **פילטרים**, **דו"חות**, **אודות**.
- בכל דף יוצגו Layout משותף, כותרת ראשית ותפריט לניווט בין כל הדפים.

#### 4.2 ניהול הוצאות – דף הבית
- טופס הוספת הוצאה יכיל את השדות הבאים:
  - **קטגוריה:** בחירה מרשימה קבועה: מזון, דלק, פנאי, רשויות, בריאות, קניות, תחבורה, דיור, חינוך, אחר, הכשרה.
  - **תיאור:** טקסט חופשי; אופציונלי, למעט כאשר נבחרה הקטגוריה "אחר".
  - **סכום:** בשקלים (₪), מספר חיובי שאינו עולה על 100,000; עד שתי ספרות אחרי הנקודה העשרונית.
  - **תאריך:** תאריך בלבד, ללא שעה; ברירת המחדל היא תאריך היום, ואפשר לבחור תאריך מוקדם יותר.
- שדות החובה: קטגוריה, סכום ותאריך. כאשר נבחרת הקטגוריה "אחר", גם התיאור הוא שדה חובה.
- אין לאפשר סכום אפס, סכום שלילי, סכום מעל 100,000 או תאריך עתידי.
- מתחת לטופס תופיע טבלת כלל ההוצאות, עם פעולות "עדכון" ו"מחיקה" לכל שורה.
- לחיצה על "עדכון" תפתח חלון Modal המכיל את נתוני ההוצאה ומאפשר לערוך אותם ולשמור את השינוי, בכפוף לוולידציה.
- לחיצה על "מחיקה" תפתח הודעת אישור. ההוצאה תימחק רק לאחר אישור המשתמש.
- טבלת ההוצאות תאפשר מיון לפי תאריך, קטגוריה וסכום באמצעות כותרות העמודות. מיון ברירת המחדל הוא לפי תאריך, מהחדש לישן.

#### 4.3 שמירת נתונים
- כלל ההוצאות יישמרו באופן קבוע ב-PostgreSQL של Supabase דרך Backend המתארח ב-Vercel.
- בעת פתיחת האתר או רענון הדף, המערכת תטען את ההוצאות ממסד הנתונים דרך ה-Backend.
- הוספה, עדכון ומחיקה יישמרו במסד הנתונים ויישתקפו בממשק רק לאחר הצלחת הפעולה.
- Local Storage אינו מקור האמת של ההוצאות. הנתונים אינם תלויים עוד בשמירת מידע בדפדפן, אלא בזמינות שירותי ה-Backend וה-Database.
- המערכת נותרת מיועדת למשתמש יחיד ללא חשבון או תהליך התחברות. לא תתווסף הרשמה או מערכת משתמשים.

#### 4.4 פילטרים – דף הפילטרים
- דף זה יכיל טבלת הוצאות עצמאית, שאינה הטבלה המוצגת בדף הבית.
- יינתן סינון לפי שנה; לפי שנה וחודש; ולפי שנה, חודש ויום.
- יינתן סינון לפי סכום הוצאה מקסימלי, כך שיוצגו הוצאות שסכומן קטן מהסכום הנבחר או שווה לו.
- ניתן יהיה לשלב סינון תאריך וסכום: הוצאה תופיע רק אם היא עומדת בכל תנאי הסינון שהוגדרו.
- הטבלה תאפשר מיון אינטראקטיבי לפי תאריך, קטגוריה וסכום, כברירת מחדל מהתאריך החדש לישן.

#### 4.5 דו"חות וגרפים – דף הדו"חות
- **Pie:** הצגת חלוקת ההוצאות לפי קטגוריות. יוצגו רק קטגוריות שיש בהן הוצאות בפועל.
- **גרף עמודות:** גרף אחד עם בחירה בין קיבוץ לפי שנים לבין קיבוץ לפי חודשים. בתצוגה החודשית המשתמש יבחר שנה.
- המשתמש יוכל לבחור האם ערכי הגרפים מייצגים **סכומי הוצאות בשקלים** או **מספר הוצאות**.
- שני הגרפים יתבססו תמיד על כלל ההוצאות השמורות, ללא השפעה של פילטרים מדף הפילטרים או של פילטרי הייצוא שבדף הדו"חות.

#### 4.6 ייצוא CSV ו-PDF – דף הדו"חות
- יופיע כפתור להורדת CSV וכפתור להורדת PDF.
- המשתמש יוכל לבחור בין ייצוא **כלל ההוצאות** לבין ייצוא **הוצאות מסוננות**.
- לצורך ייצוא מסונן יהיו בדף הדו"חות פילטרים עצמאיים לפי שנה, חודש, יום וסכום הוצאה מקסימלי, עם אפשרות לשלב ביניהם. הם אינם תלויים בבחירות שבוצעו בדף הפילטרים.
- כל קובץ יכיל את ההוצאות הכלולות בבחירה, עם פרטי ההוצאה: קטגוריה, תיאור, סכום ותאריך.
- קובץ PDF יציג את ההוצאות באופן אסתטי וברור.
- לחיצה על כפתור הייצוא תגרום להורדת הקובץ למכשיר המשתמש.
- הפילטרים המשמשים לייצוא לא ישפיעו על הנתונים המוצגים בגרפים.

#### 4.7 דף אודות
- הצגת הסבר על המערכת.
- הצגת תיאור התלמיד/ה שפיתח/ה אותה.
- הצגת תמונת התלמיד/ה.

### ב. Edge Cases & Error Handling – מקרי קצה וטיפול בשגיאות
- **אין הוצאות במסד הנתונים:** בדף הבית ובדף הפילטרים תופיע הודעה ידידותית במקום טבלה ריקה; בדף הדו"חות תופיע הודעה במקום גרפים ריקים.
- **אין התאמות לסינון:** תופיע הודעה שאין הוצאות העונות לתנאים שנבחרו.
- **קטגוריית "אחר" ללא תיאור:** הפעולה לא תאושר ותוצג שגיאת ולידציה.
- **שדה חובה חסר:** הפעולה לא תאושר ותוצג הודעת שגיאה מתאימה.
- **סכום לא תקין:** סכום שאינו מספר חיובי, גדול מ-100,000 או מכיל יותר משתי ספרות עשרוניות יידחה.
- **תאריך עתידי או לא תקין:** ההוצאה לא תישמר ותוצג הודעת שגיאה.
- **ביטול מחיקה:** לא יבוצע שינוי בהוצאה.
- **נתונים לא תקינים בעדכון:** לא תישמר גרסה לא תקינה של ההוצאה; המשתמש יוכל לתקן את הנתונים בחלון העריכה.
- **אין נתונים לייצוא המסונן:** יש להודיע למשתמש שאין הוצאות התואמות לפילטרים, במקום להציג הורדה כאילו נוצר דו"ח עם הוצאות.
- **כשל ברשת, ב-Backend או ב-Database:** יש להציג הודעת שגיאה מתאימה ולא להציג הצלחת שמירה, עדכון או מחיקה כאשר הבקשה נכשלה. יש להבחין בין מצב של אפס הוצאות למצב של כשל בטעינת הנתונים.

## 5. דרישות טכניות ואילוצים

### א. דרישות טכניות
- **פלטפורמה:** אתר Web רספונסיבי עבור Desktop ו-Mobile.
- **שפת ממשק:** עברית בלבד, בכיווניות RTL.
- **אחסון:** מסד נתונים PostgreSQL בענן Supabase, ללא שמירת הוצאות ב-Local Storage.
- **Backend:** שירות API ב-Vercel שמבצע את פעולות הקריאה והכתיבה מול Supabase.
- **Hosting:** Frontend ו-Backend ייפרסו ל-Vercel.
- **Source Control ו-Deployment:** הקוד ו-Database Migrations ינוהלו ב-GitHub. דחיפה או Merge ל-`main` תפעיל פריסת Production אוטומטית, כאשר Migrations מורצות בהצלחה לפני פריסת קוד התלוי בהן.
- **סביבות:** Supabase Development ו-Supabase Production כשני פרויקטים נפרדים, עם נתונים וסודות נפרדים.
- **פורמטים לייצוא:** CSV ו-PDF להורדה.
- **תאריכים:** תאריך ללא רכיב שעה.
- **מטבע:** שקל חדש (₪) בלבד, עם דיוק של עד שתי ספרות עשרוניות.

### ב. אילוצים
- המערכת מיועדת למשתמש יחיד וללא תהליך התחברות.
- הנתונים נשמרים בענן ומשותפים למופעי האתר הפונים לאותה סביבת Database. אין מנגנון סנכרון בזמן אמת; רענון/טעינה מחדש מביאים את המידע העדכני.
- מכיוון שהמערכת ללא התחברות, אין הפרדת נתונים או אימות זהות בין מבקרים. **כל אדם שיש לו גישה לאתר עשוי לצפות ולשנות את הוצאות המסד המשותף**. זוהי מגבלת פרטיות ואבטחה מהותית במערכת ציבורית; אין להציג אותה כמערכת להוצאות פרטיות מוגנות.
- נדרש חיבור אינטרנט תקין לצפייה בהוצאות ולשינוי שלהן; אין תמיכה בפעולה Offline.
- נדרש ניהול סודות שרת באופן מאובטח; מפתחות Supabase בעלי הרשאות כתיבה לא יישלחו לדפדפן.
- שינויי Database נבדקים תחילה בסביבת Development נפרדת. אישור השינוי ל-Production מתבצע בעת אישור Merge/Push ל-`main`; משם הפריסה אוטומטית ומותנית בהצלחת העדכון לסכימה.
- רשימת הקטגוריות קבועה כפי שהוגדרה בדרישות.
- הדרישה ל-Supabase, Vercel ו-GitHub מחייבת; בחירת Libraries ופרטי המימוש הטכני מפורטים במסמך ARCHITECTURE.md.

## 6. מה מחוץ לטווח – Out of Scope
- רישום, כניסה או ניהול חשבונות משתמשים; לכן גם אין הגנת גישה פרטנית למידע של משתמש.
- הפרדת נתונים בין חשבונות של מספר משתמשים.
- פעולת Offline, Local Storage כמקור נתונים, ושמירה מקומית במקום Supabase.
- סנכרון נתונים בזמן אמת בין חלונות/מכשירים; טעינה מחדש של האתר מביאה נתונים עדכניים.
- ניהול ושינוי של רשימת הקטגוריות בידי המשתמש.
- שימוש במטבעות שאינם שקל חדש (₪) או המרת מטבעות.
- סינון הגרפים בדף הדו"חות לפי פילטרי הייצוא: הגרפים מציגים תמיד את כלל ההוצאות.
